本版从 `AI_tingshu` 的 `a18a7c3` 快照建立，独立目录为 `D:\code\python\AI_tingshu_langgraph`，本地 Git 分支为 `langgraph`。保留原版 Git 历史，未关联远程仓库，修改不会提交到原版 GitHub。

## 版本差异

| 部分 | 原版 | 本版 |
| --- | --- | --- |
| 助手 | 手写四轮工具调用循环 | StateGraph 的模型、工具、循环保护节点；返回 graph_trace |
| 问数 | 单次生成、校验、执行 | 生成、澄清、校验、执行、有限修正节点 |
| 问数澄清 | 不支持 | interrupt 暂停，持久化 SQLite checkpoint，补充后恢复 |
| SQL 修正 | 校验失败即结束 | 字段/语法错误最多修正两次，每次重新校验；危险查询直接拒绝 |
| 查询执行记录 | 最终 SQL 与审计 | 增加节点轨迹和修正次数，管理台可展开 |
| RAG | 向量 + BM25 + RRF，原文核验 | 保留核心算法，通过助手工具节点调用 |
| 交易 | Java 状态机、模拟渠道 | 保留，模型没有新增交易写入工具 |

借鉴 `llm_customer_service/atguigu_ai/agent/graph` 示例的状态、节点和条件边设计，未复制其客服策略系统。LangGraph 不需要替换现有 HTTP 模型接口。依赖版本锁定于 requirements。

## 状态、安全与恢复边界

问数任务按管理员身份绑定，续接时重新检查 Java 管理会话与权限。待澄清任务有效期 10 分钟；其他用户无法接续，已结束或正在执行的任务不能重复提交。可刷新管理台或重启运营服务后补充口径，不需要模型记住暂停位置。

API 支持原有 `{text}`，续接支持 `{text, run_id}`；run_id 由服务返回，actor_id 由认证结果决定。图状态仅保存问题、SQL、结果和流程字段，不保存 API Key、token、数据库连接或模型客户端。检查点仍属于私有业务数据，不提交仓库。

助手保留原有 SQLite 会话和用户隔离，图执行按一次请求构建；当前不支持自动恢复失败的个人工具调用，避免把旧订单或进度当成当前事实。问数只支持恢复等待澄清的任务；其他失败需重新提问。助手的轮数限制与问数的修正次数分别计数。

数据库连接、认证、超时错误不会触发 SQL 改写；写入、跨库、关联、非白名单视图、非法函数等直接拒绝。最终数字来自只读查询结果，不由模型重新推断。额度不足和模型异常会明确失败。
