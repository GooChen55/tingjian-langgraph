# 融合设计与能力映射

本页定义本地融合版的交付范围。融合指围绕同一听书业务整合可复现的核心能力，不等于复制所有课程页面或启动全部原服务。真实微信支付、腾讯云点播与数字人按维护者安排后续准备。

## 与原听书部署的对应关系

- 用户与账户能力归入用户服务；内容及搜索业务归入内容服务与搜索投影；订单、售后和模拟支付归入订单服务。
- FastAPI BFF 负责前端路由和服务聚合，当前调用从项目 Nacos 命名空间选择健康实例，不开放任意 URL 代理。
- 搜索索引采用业务写入同事务 Outbox + RabbitMQ 投影，替代本版路径上依赖全库 Canal 监听的同步。绕过本版写接口直接修改数据库后，需要运行索引重建脚本。
- 当前核心业务与 Outbox 位于同一 MySQL 实例的项目专属 schema，可使用同一数据库事务；本版不宣称已经使用 Seata 或完成跨数据库分布式事务。
- 模拟交易维护独立回执和退款租约，保留失败、重试和人工审核事实。未来真实支付必须单独实现及验证官方签名、回调、对账与权益授予。
- Nacos 目前四份配置对应共享配置与三个实际 Java 服务；不创建没有消费者的空配置以凑原工程数量。

## 关键边界

**知识资料发布**：上传先保存不可变原件；资料修改和 Outbox 同事务提交；后台构建索引成功才激活新版，失败时旧版仍生效。删除立即从当前资料清单排除，后台完成删除状态；旧原件和审计保留，历史对话不会改写。

**消息处理**：至少一次投递，不能宣称 exactly-once。搜索读取当前业务状态，避免事件乱序恢复旧内容；知识发布检查期望版本，避免旧任务覆盖新版本。处理期间续租，I/O 线程保持 RabbitMQ 心跳，ACK 在处理完成后发送。三次失败转终态并保留死信，允许知识管理台发起新一轮重试。

**MongoDB**：进度使用统一集合，`(userId, trackId)` 唯一，按登录身份查询；并发上报原子更新。旧集合迁移保留原件。TTL 仅针对知识会话上下文，不用于长期听书进度。

**问数**：召回内容只是生成提示，最终 SQL 仍经过 AST 校验与数据库只读账号双重限制。不能访问原项目 schema 或个人明细表；最多 100 行，字段/语法错误最多修正两次。

**恢复**：售后任务与问数澄清保存在 SQLite，绑定真实身份和有效期。售后只有当前草稿、明确确认按钮及再次 Java 校验同时成立才提交，不把模型输出当作授权。

## 没有作为已完成功能宣传的内容

真实支付/退款与付费播放授权、腾讯云点播、数字人、扫描 PDF OCR/图像理解、直播、微信/App 真机、生产高可用、多实例调度与性能压测。它们不阻塞本地核心链路，但也不能写成已上线或已验证。
