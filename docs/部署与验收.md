# 部署与验收

当前验收环境为 Windows 本机应用 + `192.168.6.100` 虚拟机中间件。应用只监听本机回环地址。这是学习和面试演示环境，部署到公网前需要重新设计身份、网络、密钥、备份与监控。

## 已初始化目录启动

```powershell
cd D:\code\python\AI_tingshu_langgraph
.\Start.ps1 -Infrastructure vm -SkipBuild -UseLlm -WithKnowledge -WithOperations
.\scripts\dev\Doctor.ps1
```

打开听书端 `http://127.0.0.1:29183/listen/`，管理台 `/admin`。管理员账号为 `admin`，密码保存在本目录被 Git 忽略的 `.runtime/admin-password`。不要把运行目录发给他人或提交仓库。

默认 `-Infrastructure auto` 读取 `.runtime/environment.json`，首次运行默认为 `local`。不要用不同运行模式共享一套正在运行的进程；切换前先执行 `Stop.ps1`。Java 或前端修改后先停止，再移除 `-SkipBuild` 重新构建。Windows 会锁定运行中的 JAR。

```powershell
.\Stop.ps1
.\Start.ps1 -Infrastructure vm -UseLlm -WithKnowledge -WithOperations -JavaHome 'C:\path\to\jdk-17'
```

VM 模式的停止脚本只停止命令路径与登记身份相符的本项目应用，不停止虚拟机容器。启动脚本发现端口被其他项目占用会拒绝接管。

## 新目录与首次初始化

需要 Python 3.12+、JDK 17、Maven、Node/npm。当前完整融合链路依赖虚拟机；Windows 不需要运行 Docker Desktop。`local` 模式才需要 Docker Desktop，提供基础 MySQL/Redis/MongoDB 演示，不能代替 VM 模式的完整融合验收。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements/requirements.lock.txt
npm --prefix frontend/uniapp ci
```

首次 VM 初始化在 `.runtime/vm-bootstrap-private.json` 中准备以下字段，值由环境维护者填写，不使用文档中的占位符启动：

```json
{
  "host": "192.168.6.100",
  "ssh_user": "root",
  "ssh_port": 22,
  "ssh_password": "<本机填写>",
  "mysql_password": "<本机填写>",
  "rabbit_user": "<已有管理账号>",
  "rabbit_password": "<本机填写>"
}
```

先确认虚拟机已有 MySQL 8、Redis、RabbitMQ 管理 API、Nacos 与 Elasticsearch 8，且端口可达。初始化脚本创建专属资源，遇到同名但没有本项目归属的资源会拒绝接管。

```powershell
.\.venv\Scripts\python.exe scripts/setup/ProvisionVm.py          # 查看固定资源范围
.\.venv\Scripts\python.exe scripts/setup/ProvisionVm.py --apply
.\.venv\Scripts\python.exe scripts/setup/DeployVmMongo.py
.\.venv\Scripts\python.exe scripts/setup/DeployVmAi.py
. .\scripts\dev\VmEnvironment.ps1
Set-TaskVmEnvironment $PWD.Path
.\.venv\Scripts\python.exe scripts/setup/MigrateMongoProgress.py
.\.venv\Scripts\python.exe scripts/setup/BuildSearchIndexes.py
.\Start.ps1 -Infrastructure vm -UseLlm -WithKnowledge -WithOperations
```

`infra/vm/docker-compose.ai.yml` 当前固定了已经在此 VM 验证的镜像。其中 MinIO 引用宿主机镜像 ID，设置 `pull_policy: never`；它依赖当前 VM 缓存，不能宣称任意新 VM 一键复现。新 VM 需先准备相同镜像，或在本项目 Compose 中换成经过兼容验证的可拉取镜像。数据卷与容器必须保留 `aillisten.owner=aillisten-dev/v1` 标签；不能复用其他项目的数据目录。SSH 首次连接的主机指纹应与 VM 控制台核对。

## 资源隔离清单

| 资源 | 本项目范围 |
| --- | --- |
| MySQL | 九个 `aillisten_dev_*` 库；应用账号 `aillisten_dev_app`；问数账号 `aillisten_dev_reader` 仅能读取六个聚合视图 |

| Nacos | namespace `aillisten-dev`，group `AILLISTEN_DEV`，公共配置加三个服务配置 |
| ES | 精确允许的 `aillisten-dev-*` 索引，由代码白名单进一步约束；共享 ES 当前没有项目级服务端鉴权，隔离依赖应用约束 |
| MongoDB | 独立容器与端口 37017，数据库 `aillisten_dev` |
| AI 服务 | 独立容器、网络与卷；MinIO 39000/39001、Milvus 39530/39091、Qdrant 36333/36334、Neo4j 47474/47687 |

公共 MySQL/Redis/Rabbit/Nacos/ES 的全局配置不由本项目修改。共享 Redis 没有持久化项目 ACL 时，VM 重启后启动预检只恢复本项目 ACL；如果共享服务本身未启动，应由环境维护者排查，脚本不接管容器。

应用端口为 29183（H5/管理台/助手）、29184（知识）、29185（问数）、19201（用户）、19202（内容）、19204（订单）。Nacos 注册回环地址是当前 Windows BFF 调用拓扑，不能直接作为跨主机生产注册方案。

## 数据、模型与恢复

SQL 按文件名、校验和和执行时间登记迁移，已执行文件不可修改，新增迁移使用下一个版本号。VM 模式会把原 SQL 中的库名映射到专属库；不会修改原始 SQL 或其他项目的库。MySQL DDL 不是整文件事务，失败后检查报错并按幂等迁移恢复，不删除数据库或卷。

模型在管理台分别配置对话与向量供应商。对话连接测试覆盖 JSON 与工具调用，向量测试校验实际维度；保存配置本身不代表测试通过。密钥用当前 Windows 账户 DPAPI 加密，VM 模式存于 `.runtime/vm/model-settings.json`。迁移到另一台电脑或 Windows 用户后需要重新填写密钥。

VM 模式会话、检查点、向量缓存与文档构建状态位于 `.runtime/vm`。退款状态与回执在 MySQL；售后图状态与问数澄清保存在 SQLite；知识上下文还使用独立 MongoDB TTL 集合。备份时同时保留数据库、对象存储、专属 AI 数据卷和本机状态目录，密钥单独保护。文档删除立即退出有效语料，历史对象与旧版本向量保留审计，尚未实现自动回收策略。

## 复现验收

```powershell
.\scripts\dev\VerifyAll.ps1
.\scripts\dev\VerifyAll.ps1 -Live
```

`-Live` 会调用真实模型、产生供应商用量，并新增明确标记的模拟账号和订单；包含订单服务实际重启。它不执行真实资金操作。完整融合新增链路还需以下专项验收：

```powershell
. .\scripts\dev\VmEnvironment.ps1
Set-TaskVmEnvironment $PWD.Path
.\.venv\Scripts\python.exe scripts/verify/VerifyFusion.py --phase prepare
.\Stop.ps1
.\Start.ps1 -Infrastructure vm -SkipBuild -UseLlm -WithKnowledge -WithOperations
.\.venv\Scripts\python.exe scripts/verify/VerifyFusion.py --phase accept
.\.venv\Scripts\python.exe scripts/verify/VerifySearchSync.py
.\.venv\Scripts\python.exe scripts/verify/VerifyMongoProgress.py
node scripts/verify/VerifyBrowser.cjs
```

准备与恢复须在售后任务十分钟有效期内完成。浏览器验收使用项目 devDependency Playwright 和本机 Edge；默认不会操作用户已经打开的浏览器。

其他项目隔离对比在变更前运行 `VerifyVmIsolation.py --capture` 保存基线，结束运行 `VerifyVmIsolation.py`。已有基线不允许覆盖。当前目录还保留了外部 VM 重启前后的观察证据，详见 [融合验收记录](融合验收记录.md)。

## 请求与排错

AI 请求默认每令牌每分钟 30 次、单实例最多并发 4 个，总处理时间上限 120 秒；这是单进程限流。超时返回 504，过载返回 429。SSE 上报真实节点进度和最终结果，未实现逐 token 生成。

响应 `x-request-id` 贯穿 Python 与 Java。运行日志不记录令牌、密钥或完整提示词；问数另存已授权 SQL 与口径审计。先检查 Doctor、`.runtime` 内对应服务日志和错误编号，再检查中间件与模型。不要把私有日志直接贴到公共 issue。

个人知识空间新增 SQL 13 与服务模块；已初始化目录升级时，先运行 `scripts/setup/ProvisionVm.py --apply` 应用专属迁移，再重启 Python 与工作进程、重新构建 H5。详见 [个人知识空间与云接入](个人知识空间与云服务接入.md)。
