# 开发与贡献

## 准备环境

参考 [项目首页](../README.md) 建立 `.venv` 并安装锁定依赖。Windows 本机开发需要 JDK 17、Maven、Node.js 和 Python；VM 模式不需要本机 Docker Desktop，local 模式需要 Docker Desktop；对话和向量密钥通过本机管理台配置。

```powershell
git switch -c feat/your-change
.\.venv\Scripts\python.exe -m pytest tests -q
```

前端变更在 `frontend/uniapp` 执行 `npm ci` 和 `npm run build:h5`。Java 与联调验收通过 `scripts/dev/VerifyAll.ps1` 执行，`-JavaHome` 指向本机 JDK。修改源码后重新构建并启动，再验证实际页面或业务入口。

## 修改约定

- 源码分别放在 `backend`、`frontend` 和 `python`；自动生成的文件不能代替源码提交。
- 已执行的 SQL 迁移有校验和，不修改旧迁移；新增独立版本并同步初始化及验收说明。
- 助手和问数继续遵守身份隔离、只读查询及工具边界；交易由明确的业务入口提交。
- 测试应覆盖实际行为与边界。模型、向量维度、认证或交易变更，还需相应的真实服务验收。
- 保留第三方版权和来源说明，不为整个混合来源工程添加未经确认的统一开源许可证。

## 自动检查

GitHub Actions 在提交到 `main` 或提出 Pull Request 时运行 Python 单测、Java 单测和 H5 生产构建。Python 在 Windows runner 执行，以覆盖当前 Windows 账户加密路径；Java 和 H5 在 Linux runner 检查构建可移植性。

自动检查不启动数据库、不请求真实模型、不执行模拟交易重启验收，不能替代 [部署与验收](部署与验收.md) 中的本机联调。工作流仅授予读取仓库权限，第三方 Action 固定到提交版本，不上传运行数据和构建产物。

## 提交前

```powershell
git diff --check
git status --short
git diff --stat
```

检查暂存内容，确保不包含 `.env`、API Key、密码、私有日志、数据库、个人简历或截图中的个人资料。`.runtime`、`.venv`、`output` 和 `tmp` 已排除；添加新目录时仍需核对。

Pull Request 写明问题、完成后的行为、验证结果与尚未验证的范围。反馈问题时提供入口、复现步骤、预期和实际结果；日志先脱敏。
